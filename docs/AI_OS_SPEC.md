# FinbyzAI OS — Specification

**From agent executor to an autonomous AI operating system for Frappe/ERPNext**

| | |
|---|---|
| Status | Draft v0.1 |
| Date | 2026-07-11 |
| Scope | `finbyzai` app only. Consumer apps (`ai_crm`, `chatforge`, `finbyzreach`, `finbyzweb`) are in production and are **never modified** — they inherit everything through `AgentService.invoke()`. |
| Supersedes | The instrumentation-only plan (its Phase 0/1 are absorbed here as Phase 0/1). |

---

## 0. Why this document

`finbyzai` today is an **agent execution engine**: a human designs a workflow (agent → prompt → tools → schema), wires it into a doctype, and code calls `AgentService(name).invoke(query)`. That design has a hard ceiling — no matter how well we polish it, the human remains the planner, the scheduler, the memory, and the QA department.

This spec designs the end state first — what the ideal enterprise AI platform on Frappe looks like in five years — and then works backwards into phases that each ship standalone value starting from the current codebase.

The thesis: **the ERP already is an operating system for a business** — it has users, permissions, a filesystem (DocTypes), schedulers, and an audit trail. The AI platform should not sit *beside* it as a chat toy; it should become the ERP's **process layer**, where humans state goals and review exceptions, and agents do the work in between.

Nobody in the Frappe ecosystem has this. `frappe/flow` persists runs but cannot replay or learn from them. Raven exposes CRUD tools but has no planner, no router, no memory. Neither has evals, cost attribution to ERP dimensions, or autonomous goal decomposition. This is the open lane.

## 1. The architectural critique — why the current design caps out

Each point is grounded in the actual code, not hypothetical.

### 1.1 Function calls, not processes

`AgentService.invoke()` runs synchronously inside whatever worker called it (web request or RQ job). Evidence: every consumer call site (`ai_crm/utils/perplexity.py:35`, `chatforge .../chatbot_settings.py`, etc.) blocks on `invoke()`.

Consequences: a long agent loop ties up a gunicorn worker; nothing can be paused for human approval mid-run; a crash loses all progress; there is no way to run a 40-step plan overnight. **Autonomy requires durable, resumable executions — processes, not function calls.**

### 1.2 Humans compile the workflow

The `AI Agent` doctype is a hand-assembled program: which LLM, which tools, which prompt messages, which output schema. `ai_crm` alone maintains a dozen such hand-wired agents (`company_research_agent`, `person_research_agent`, `helper_agent`, ...). Every new use case is a configuration project. **Autonomy inverts this: the system composes agent+tools+model per goal, at runtime.**

### 1.3 Amnesia by design

Nothing survives a run. `FrappeChatMemory` (`ai/memory/base.py`) is the only persistence bridge and it is (a) never used — `AgentService.get_memory()` returns raw in-process LangChain memories — and (b) broken — it reads `m.role` while `AI Conversation Message` defines `message_type`. Runs 1..N of the same task teach run N+1 nothing. **A system that cannot remember cannot improve.**

### 1.4 The wrapper trap

LangChain's abstractions are load-bearing everywhere: `initialize_agent` + `AgentType` (deprecated upstream), `ConversationBufferMemory` et al. (deprecated in LC 0.3), `AgentExecutor`. `structrued_agent.py:111` even mutates a module-level prompt singleton in place — prompts accumulate across calls in a long-lived worker. The app's durable value (doctypes, permissions, KB, ERP data) is welded to a framework layer that churns every 12 months. **Invert the dependency: the OS owns state, governance, and memory; LLM frameworks become swappable drivers.**

### 1.5 No identity, no governance

Agents run as whoever triggered them, and persistence sprinkles `ignore_permissions=True` (`memory/base.py:24,50`). There is no notion of *what an agent is allowed to do*, no approval gate, no kill switch. `AgentAsTool._run` (`agent_as_tool.py:89`) converts every sub-agent exception into a string the parent LLM happily treats as data. Also: a **hardcoded LangSmith API key** at `agent_service.py:27` ships every production prompt to an external SaaS. **Enterprise autonomy is a governance product first and an AI product second.**

### 1.6 Tools don't scale

Every tool is a hand-written Python file code-generated by the `AI Tool` doctype. The ERP already describes itself completely — DocType metadata, permissions, link fields, reports. **Tools should be *derived* from metadata with permissions enforced, not authored one by one.** (Raven proved the pattern with 18 CRUD function types; we go further by making them permission-scoped per agent identity.)

### 1.7 Zero observability

No tokens, cost, latency, or trace persisted anywhere (verified by grep: no `usage_metadata`, `completion_tokens`, cost handling). You cannot govern, route, or learn from what you cannot see. Observability is not a feature of the OS — it *is* the kernel.

## 2. North star — five years out

### 2.1 Thesis

> **Exception-driven management.** Every recurring business process in the ERP has an AI process counterpart. Humans set goals, budgets, and boundaries; agents plan and execute; humans see only exceptions and approvals. The system gets measurably better every week because every run feeds memory, evals, and routing statistics.

### 2.2 The OS metaphor (this is load-bearing, not decoration)

| OS concept | FinbyzAI OS equivalent |
|---|---|
| Process | **AI Process** — durable, resumable execution of a goal |
| Process tree / fork | Sub-agent spawning with depth, budget, and permission inheritance caps |
| Scheduler | Orchestrator on Frappe RQ queues; priorities, deadlines, preemption (pause/resume) |
| Syscall | **Tool call** — the only way an agent touches the world |
| Ring protection | Frappe permissions via **agent identity** (a real `User` with scoped roles) + approval gates for privileged syscalls |
| Filesystem | DocTypes — already versioned, permissioned, audited |
| RAM / paging | Working memory (process blackboard) → episodic (runs) → semantic (facts) → procedural (skills) |
| Watchdog | Budget circuit-breakers, timeouts, global kill switch |
| Syslog | AI Run trace log (kernel-level, cannot be opted out of) |
| Package manager | Skill library — distilled, versioned, shareable playbooks |
| Drivers | Pluggable LLM runtimes (LangGraph today; native LiteLLM loop, Claude Agent SDK, or future frameworks later) |

### 2.4 The autonomy loop (heart of L2/L3)

For each `AI Task` in a process:

```
PLAN ──► ACT ──► OBSERVE ──► REFLECT ──┬─► accept → next task
 ▲                                     ├─► retry (same strategy)      [attempt < max]
 │                                     ├─► retry with reflection note
 │                                     ├─► escalate model (router ladder)
 └───────────── replan ◄───────────────┼─► revise plan (add/remove tasks)
                                       ├─► ask human (approval/input gate)
                                       └─► abort (budget/deadline/depth breached)
```

**Confidence** that drives the branch is composite, never a single self-report:
1. Hard validators — output schema, business-rule assertions attached to the task
2. Model self-assessment (cheap, weak signal)
3. Historical prior — success rate of this (task-class, model) pair from run/eval stats
4. Optional cross-model verification for high-stakes tasks (a second, different model grades the output)

**Guards** (kernel-enforced, not prompt-enforced): `max_attempts`, `max_depth` (sub-process nesting), `max_cost`, `deadline`, allowed-doctype allowlist. A prompt can be jailbroken; a budget check in Python cannot.

### 2.5 Governance rings

- **Ring 0 (auto):** reads, drafts, internal writes to agent-owned doctypes
- **Ring 1 (post-audit):** writes the agent's role profile permits; logged, reversible via document versioning
- **Ring 2 (pre-approval):** outward-facing or financial actions — emails to customers, submitting documents, payments — block on an **AI Approval** with `frappe.publish_realtime` notification + assignment; process checkpoints and resumes on decision
- **Ring 3 (forbidden):** enumerated never-do list per agent identity (e.g. delete, cancel, user management)

Every agent is a real Frappe `User` (bot type) with real roles. Permission enforcement is Frappe's, not ours — we inherit 15 years of hardening.

### 2.6 Memory hierarchy

| Layer | Store | Written by | Read by |
|---|---|---|---|
| Working | `AI Process.state` JSON blackboard | executor | all tasks in the process |
| Episodic | `AI Run` / `AI Run Step` | kernel tracer (always) | reflector, router, replay, evals |
| Semantic | `AI Memory` doctype, embedded via existing KB/vector-store layer | reflector ("learnings"), humans | planner & agents via auto-injected recall tool |
| Procedural | `AI Skill` — a distilled, parameterized plan template with preconditions + success stats | skill distiller (Phase 6), humans | planner (searches skills *before* planning from scratch) |

The flywheel: successful novel plans → skills; skills make future planning cheaper and more reliable; failures → eval cases; eval stats → router priors; human corrections → feedback memory. **This loop is the moat — it compounds, configuration doesn't.**

### 2.7 The economic layer

Cost is a first-class kernel signal, not a report:
- Every run metered (tokens × `litellm.cost_per_token`, verified working for 2,949 models; degrades to NULL when unknown)
- Budgets per agent / process / user / month with circuit breakers
- Attribution to ERP dimensions — Cost Center, Project, Customer — via context stamped on `AI Run`. *Only an AI platform living inside an ERP can do this; chat apps have no ledger.*
- The router treats budget remaining as an input: burn low → cheaper ladder

### 2.8 A day in the life (north-star walkthrough)

Goal typed by a manager: *"Recover overdue receivables > 60 days this month. Don't contact disputed accounts. Budget ₹2,000 of AI spend."*

1. **Planner** (L3) searches skills, finds `collect-receivables` v7 (learned 4 months ago, 78% success), instantiates it into an `AI Process` with a task graph: fetch AR aging → exclude disputed (semantic memory holds "Customer X disputes invoice Y") → segment by history → per-customer sub-process: draft reminder in the tone that historically worked for that segment → Ring-2 gate for key accounts → send → watch replies → log promises-to-pay as ToDos for humans.
2. **Router** (L3) runs drafting on a Small model, escalates the three hostile-history accounts to a reasoning model.
3. **Executor** (L2) runs 40 sub-processes over 3 days on RQ, checkpointing; the manager approves 4 gated emails from their phone; one customer replies angrily → reflector flags low confidence → ask-human exception.
4. **Learning** (L4): 31 paid or promised. Reflection updates the skill's per-segment template stats; the angry-reply case becomes an eval case; total spend ₹1,340 lands on the Receivables cost center, per-customer.

Human time invested: one sentence and five approvals.

## 4. Roadmap — working backwards into phases

Capability ladder the phases climb: **L0 assisted (today) → L1 observable → L2 durable → L3 governed → L4 autonomous-bounded → L5 learning → L6 ecosystem.**

Each phase ships standalone value; nothing waits for the vision to be complete.

### Phase 0 — Kernel hygiene *(days; ship immediately)*

**Goal:** stop the bleeding; make the platform honest.

- Delete the hardcoded LangSmith key + forced tracing (`agent_service.py:27-28`); **rotate the key** (it's in git history)
- Tracing backend selected via `frappe.conf` (`finbyzai_tracing_backend`: `native` default), never env-at-import
- Pass `temperature` / `max_tokens` from `AI Agent` into `ChatLiteLLM` (fields verified accepted; currently silently dropped)
- Fix `AgentAsTool._run`: raise `ToolException` instead of returning error strings to the parent LLM
- Fix `structrued_agent.py` module-level prompt mutation (copy before splice)
- Add missing `langchain-openai` to `pyproject.toml`

**Exit:** `grep -rn "lsv2_pt_" .` empty; agent with `temperature=0` is deterministic; a raising sub-agent fails loudly.

### Phase 1 — The syslog: AI Run tracing *(the foundation everything reads)*

**Goal:** every LLM/tool/chain event persisted natively; cost metered.

- **New doctypes:** `AI Run` (agent, user, status, started/ended, duration_ms, input/output, error, prompt/completion/total tokens, cost, model, trace_id, `replayed_from`, attribution fields: cost_center/project/party/reference doc) and `AI Run Step` (child: parent_step, step_type llm/tool/chain/retriever, name, input/output/error, tokens, cost, duration_ms)
- **New module** `finbyzai/ai/observability/`: `FrappeTracer(BaseCallbackHandler)` — buffers in memory, writes once at run end, never raises into the run; cost via `litellm.cost_per_token` with NULL fallback
- Wire in exactly one place: `AgentService.invoke()` passes `config={"callbacks":[tracer]}` down. **All four consumer apps light up with zero changes.**
- Desk trace-tree view on AI Run; retention job (archive runs > N days)

**Exit:** every consumer-app call produces an `AI Run` with real tokens+cost; a deliberately failing tool shows an errored step; overhead < 50ms per run.

### Phase 2 — Processes: durable, resumable, streamable *(L2)*

**Goal:** kill the function-call model.

- **New doctypes:** `AI Process` (goal text, initiator, status Draft/Running/Waiting-Approval/Waiting-Input/Paused/Completed/Failed/Killed, `state` JSON blackboard, budget fields, deadline, parent_process, depth) and `AI Task` (child-ish but non-table: sequence, depends_on, agent/skill used, attempts, status, validator schema, reflection notes)
- Executor runs on RQ (`long` queue), checkpoints after every task, resumes from checkpoint on worker restart
- `frappe.publish_realtime` streaming of task/token progress (consume the existing `ReactAgent.stream()`)
- Kill switch: single-click process kill; site-wide `AI Settings` pause toggle
- Sync `invoke()` remains untouched for consumers; processes are a new entry point

**Exit:** a 10-task process survives `bench restart` mid-run and completes; live progress visible in desk; kill works mid-task.

### Phase 3 — Governed hands: identity, generated tools, approvals *(L3 governance)*

**Goal:** agents act *as someone*, with rings.

- **Agent identity:** `AI Agent` gains `run_as_user` (bot User) + role profile; executor wraps task execution in `frappe.set_user(run_as_user)`; remove `ignore_permissions=True` from the platform
- **Generated tools:** `AI Tool` gains `tool_source = Custom | Package | Generated | MCP`; Generated tools derive from DocType metadata (get/list/create/update/submit/report/search) and enforce the *agent identity's* permissions at call time — Raven's idea, but permission-scoped per identity rather than global
- **New doctype `AI Approval`:** ring-2 gate; blocks process at checkpoint, notifies (realtime + assignment), resumes on approve/reject with the decision fed back into the loop
- Ring-3 denylist per agent identity

**Exit:** an agent whose identity lacks write on Sales Order gets a permission error when its tool tries; a ring-2 email drafts, waits, sends only after human approval; every doc touched by an agent shows the bot user in its version history.

### Phase 4 — Cognition I: planner + reflection + retry *(L4 core)*

**Goal:** goal in, plan out, self-correcting execution. This is the autonomy inflection.

- **Planner:** a system agent that decomposes a goal into an `AI Process` task graph (JSON schema-validated via existing `json_schema_to_pydantic` path), declaring per-task: needed tool classes, validator, ring level, budget share
- **Reflector:** after each task, run the composite-confidence check (validators → self-score → historical prior); branch per the autonomy loop (§2.4); reflection notes stored on the task and injected into retries
- **Sub-process spawn** as a syscall with inherited-and-capped budget/depth/permissions; replaces the error-swallowing `AgentAsTool` path inside processes
- Plan revision: reflector may propose graph edits; ≤ N revisions, else ask-human
- Guards enforced in Python, not prompts

**Exit:** "Research these 5 companies and produce a comparison doc" runs from a one-line goal with zero pre-wired workflow — planner decomposes, one sub-task fails and self-retries with reflection, output validates, total cost within budget.

### Phase 5 — Cognition II: the model router *(L4 economics)*

**Goal:** stop hardcoding models per agent; choose per task.

- **New doctype `AI Model Policy`:** task-class → model ladder (e.g. extract: Small→Medium; reason: Medium→Large-reasoning), constraints (vision, context size), budget-aware degradation rules
- Router inputs: task class, required capabilities, context size, budget remaining, deadline, historical success of (task-class, model) from Phase-1 run data
- Escalation on reflect-fail climbs the ladder before replanning
- Seeds already in data: `LLM.size` (40/40), `is_reasoning` (15), `supports_vision` (21) — plus live cost from the kernel
- `AI Agent.llm` becomes a *default*, overridable by policy inside processes

**Exit:** the same goal executes measurably cheaper (>30% on a benchmark set) with equal eval pass rate, by routing easy tasks to Small models; router decisions visible per task in the trace.

### Phase 6 — Memory & learning: the flywheel *(L5)*

**Goal:** run N+1 is better than run N, provably.

- **`AI Memory`** (semantic): scoped facts (global/agent/party/doctype), embedded through the existing KB/vector layer; written by reflector ("learning: Customer X requires PO number on invoices") and by humans; auto-injected recall tool in every process
- **`AI Skill`** (procedural): distilled from ≥ k successful processes of the same goal class — parameterized task-graph template + preconditions + success/cost stats; planner searches skills first; skills are versioned doctypes → exportable as fixtures (the "package manager")
- **Evals:** `AI Eval Set` / `AI Eval Case` / `AI Eval Run`; one-click "promote this AI Run to eval case"; scheduled runs; assertion types: contains / json-schema / exact / LLM-judge
- **Replay & diff:** re-execute any stored `AI Run`/`AI Process` against a new model/prompt/skill version; side-by-side output/cost/latency diff — *the ecosystem-first feature: runs become experiments*
- **`AI Feedback`:** capture human edits to agent output (diff of draft vs sent) as training signal for skill/prompt revision
- Router priors update from eval + run stats (closing the L4↔L5 loop)

**Exit:** a skill's success-rate stat visibly improves across versions; a prompt change is blocked by a failing eval before it ships; replay of last week's run under a new model produces a decision-ready diff.

### Phase 7 — Ecosystem & interfaces *(L6)*

**Goal:** open the platform out.

- **Goal inbox:** desk chat page (Vue) — type a goal, watch the plan stream, approve inline; mobile-friendly approvals
- **`AI Trigger` doctype:** launch processes from doc_events / schedule / inbound email / webhook (generalizes today's hardcoded hooks)
- **MCP both directions:** consume external MCP servers as `tool_source=MCP`; expose generated tools via `frappe/mcp` (experimental upstream — keep behind a flag)
- **Attribution dashboards:** spend by agent/model/cost-center/customer (query reports over AI Run — no new infra)
- Consumer apps *optionally* migrate from `invoke()` to processes at their own pace; `invoke()` stays supported forever
- Candidate open-source extraction: kernel + process layer as a community app (the "solve it for the whole Frappe community" play)

**Exit:** a goal submitted from chat runs end-to-end with approvals on mobile; an external MCP tool participates in a plan; a monthly AI spend report by Cost Center goes to accounts.

## 5. Design invariants (hold across all phases)

1. **Everything is a DocType.** Plans, runs, skills, memories, approvals, policies — inspectable, permissioned, exportable as fixtures. No opaque state in Redis/pickles beyond transient checkpoints.
2. **The kernel cannot be bypassed.** All model/tool traffic flows through the tracer and budget checks. No direct `ChatLiteLLM` construction outside the driver.
3. **Guards live in Python, not prompts.** Budgets, rings, depth caps are code; prompts merely inform the model of them.
4. **Drivers are replaceable.** `Driver.execute(StepSpec) -> StepResult` is the boundary; LangChain/LangGraph types never appear above it. (Today's `AgentService` becomes the first driver, wrapped, not rewritten.)
5. **Frappe-native over reinvention.** Permissions, RQ, realtime, versioning, assignments, Workflow — use them; our value is the cognition and learning layers, not plumbing.
6. **Humans can always override.** Pause, kill, edit a plan mid-flight, revoke a ring. Autonomy is a dial per agent/process, not a switch.
7. **Consumer apps never break.** `AgentService.invoke()` signature is frozen; new capability arrives as new entry points.
8. **Degrade gracefully.** Unknown model pricing → NULL cost, not a crash; missing skill → plan from scratch; tracer failure → run proceeds, error logged.

## 6. Honest risks & open questions

- **Planner reliability** is the hard problem; mitigation: skills-first planning (most executions instantiate a proven template, cold planning is the fallback), strict schema validation, ring gates on all writes.
- **Cost of cognition:** reflection/planning tokens can exceed task tokens on small tasks; router must give trivial tasks a no-reflection fast path.
- **Child-table bloat:** AI Run Step at production volume needs indexes + retention/archival from day one (Phase 1 includes it).
- **LangGraph checkpointing vs our own:** Phase 2 could adopt LangGraph checkpointers instead of a custom blackboard; decide by spike — but the *doctype* remains the source of truth either way (invariant 1).
- **`frappe/mcp` is explicitly experimental upstream;** keep MCP exposure flagged.
- **Frappe v15 / Python 3.11 constraints:** current stack (langchain 0.3 / langgraph 0.6) already runs; driver isolation is our hedge against upstream churn.
- **Agent identity UX:** one bot user per agent may proliferate users; consider one bot user per *ring profile* if that gets noisy.
